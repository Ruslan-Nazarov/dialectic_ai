# Архитектурный промпт: движок версии 3

Это жёсткая спецификация для написания третьей версии движка с нуля. Правила со словом «ОБЯЗАТЕЛЬНО» и
«ЗАПРЕЩЕНО» не обсуждаются в ходе реализации; если правило мешает — остановиться и спросить владельца.
Источник метода — алгоритм владельца «версия движка 3» (далее — Алгоритм, ссылки вида «А 4.2»). Опыт
версии 2 — `ENGINE_V2_LESSONS.md`.

---

## 1. Что строим

Движок строит **мир области**, в котором действует агент, и даёт агенту этим миром пользоваться.

- **Построитель мира.** По описанию области (например, «проверка договоров о неразглашении») строит мир по
  Алгоритму: простейший процесс P0 → итерации развития → противоположность → противоречие → разрешение.
- **Мир** — хранимый объект с версиями. Строится один раз на область.
- **Адаптер.** Подмешивает знание мира в обычную работу любого агента (его рассуждения, планирование,
  выбор действий). Алгоритм не определяет, что делать агенту; он определяет, в каком мире агент делает то,
  для чего задуман.
- **Локальный пересмотр.** Если данные, полученные агентом, не укладываются в мир, меняется только та часть
  мира, которая связана с ошибкой, новой итерацией (А 4.6). Весь мир не перестраивается.

## 2. Жёсткие принципы

1. **Блоки программные.** ОБЯЗАТЕЛЬНО: каждый пункт Алгоритма, который что-то порождает, — отдельный блок
   в коде. Код создаёт блоки, задаёт их порядок, итерации, пределы и связи. Внутри блока нейросеть делает
   только то, что Алгоритм поручает ей в этом пункте, и получает только данные этого блока.
   ЗАПРЕЩЕНО: один промпт, который строит весь мир или его каркас сразу.
2. **Судьи нет.** ЗАПРЕЩЕНО: отдельная модель, проверяющая результаты блоков; отдельный шаг проверки по А 9.
   Код проверяет только форму: разобран ли JSON, есть ли обязательные поля, записан ли процесс как переход,
   существуют ли ссылки, соблюдены ли пределы. Требования Алгоритма (включая А 9) входят в задание
   нейросети внутри блока.
3. **Процесс — это переход.** ОБЯЗАТЕЛЬНО: каждый процесс в мире записан как переход одного процесса в
   другой (А 1.1): поля `from` и `to` плюс краткая формулировка. Блок, вернувший процесс не как переход,
   переспрашивается (проверка формы).
4. **Передача между блоками.** Каждый блок получает сжатую передачу от предыдущего блока плюс те элементы
   мира, которые нужны его пункту. Если последнему блоку нужно что-то из первого — это передаётся.
5. **Экономия.** Никаких лишних вызовов. Мир строится один раз на область. Независимое выполняется
   параллельно. Токены и время учитываются в каждом прогоне.
6. **Пределы — настройки.** Все числа из раздела 6 — в конфигурации, не в коде.
7. **Ничего из протокола версии 2.** ЗАПРЕЩЕНО переносить: судью, протокол из 14 ходов, правила мира
   версии 2, псевдонимы идентификаторов, «клиринг» ходов. Разрешено переносить (копированием, не импортом из
   `engine_v2/`): подключение моделей, повторы при сбоях, извлечение JSON из ответа, учёт токенов.

## 3. Модель данных мира

```text
World
  id, domain (описание области), version, created_at, parent_version
  p0: P0Record
  bundles: {"p0": Bundle, "opposite": Bundle, "contradiction": Bundle}
  opposite: Opposite | None
  contradiction: Contradiction | None
  resolution: Resolution | None
  revisions: [Revision]          # журнал пересмотров
  status: "built" | "no_opposite" | "failed"

Process                         # всегда переход (А 1.1)
  id, from, to, statement
  role: "p0" | "developing" | "internal" | "resolution"
  bundle: "p0" | "opposite" | "contradiction"
  iteration: int                 # на какой итерации появился
  derived_from: [process_id]     # из чего вытекает (А 4.2, 4.3); для первого — P0 или корень пучка
  parent_id: process_id | None   # для внутреннего — его развивающий процесс (А 4.5)
  links_prev: [process_id]       # для внутреннего — связанные внутренние того же P на прошлой итерации (А 4.5)
  status: "active" | "retired"   # retired — убран на следующей итерации (А 4.6)

P0Record
  process_id
  from_leap: str                 # разрешением какого противоречия является P0 (А 3.1(1)); движок не проверяет
  attempt: int

Bundle
  root_id                        # P0, противоположность или противоречие
  iterations: [Iteration]

Iteration
  n, variant: 1 | 2 | 3          # вариант А 4.6 (для первой итерации — нет)
  developing: [process_id]       # активные развивающие процессы этой итерации
  internal: {developing_id: [process_id]}
  comparison: Comparison

Comparison                      # результат А 4.7
  vs_root: str                  # развивающие vs простейший (корень пучка)
  among: str                    # развивающие между собой
  internals: str                # внутренние одних vs внутренние других
  opposite_candidate: process_id | None, why_not_required: str   # только для пучка P0 (А 4.8, 5, 5.1)
  next_variant: 1 | 2 | 3 | None, next_changes: str               # выбор нейросети для следующей итерации
  sufficient: bool              # для пучков противоположности и противоречия: развития достаточно

Opposite: process_id, why_not_required (А 5.1)
Contradiction: statement, unity (А 6)
Resolution: process_id, kind: "replacement" | "mediation", explanation (А 7, 7.1)
Revision: at, trigger (данные агента), affected [process_id], new_version, summary
```

Мир сохраняется в JSON-файл на каждую версию (`worlds/<domain_slug>/v<N>.json`). Старые версии не
перезаписываются.

## 4. Блоки построителя мира

Каждый блок — класс или функция с одним вызовом нейросети (если не сказано иное), своей схемой ответа и
проверкой формы. При плохой форме — повтор с указанием ошибки, не больше `form_retries`.

| Блок | Пункт | Получает | Возвращает |
|---|---|---|---|
| `FindP0` | А 3, 3.1 | описание области; при повторе — отвергнутые P0 и почему | P0 как переход; `from_leap` |
| `NextDeveloping` | А 4.1–4.3, 2.1, 9 | корень пучка; уже полученные развивающие этой и прошлых итераций; передача | ОДИН следующий развивающий процесс как переход и `derived_from` |
| `Internals` | А 4.5, 9 | один развивающий процесс (как простейший); его внутренние на прошлой итерации | внутренние процессы глубины 1; `links_prev` |
| `Compare` | А 4.7, 4.8, 5, 5.1 | корень, развивающие этой итерации с внутренними | `Comparison` |
| `Contradiction` | А 6 | P0, противоположность, пучок противоположности (сжато), передача | противоречие |
| `Resolve` | А 7, 7.1 | противоречие, пучок противоречия (сжато), P0, противоположность | разрешающий процесс как переход, вид, объяснение как разрешение |

### 4.1. Пучок с итерациями (общий механизм для трёх пучков)

Код, не нейросеть, ведёт пучок:

1. Итерация 1: `NextDeveloping` вызывается последовательно `developing_per_iteration` раз — каждый
   следующий процесс вытекает из корня и уже полученных (А 4.2). Последовательно, не параллельно.
2. `Internals` — для каждого развивающего процесса, **параллельно** (они независимы).
3. `Compare` — один вызов на итерацию.
4. Остановка:
   - пучок P0: `opposite_candidate` найден → стоп; иначе следующая итерация;
   - пучки противоположности и противоречия: `sufficient` → стоп; иначе следующая итерация;
   - предел `iterations_max` → стоп.
5. Следующая итерация выполняет выбранный нейросетью вариант А 4.6 (`next_variant`, `next_changes`):
   - 1 — состав развивающих прежний, `Internals` заново (с `links_prev`);
   - 2 — `NextDeveloping` добавляет процессы и/или код помечает убираемые `retired`; внутренние прежние;
   - 3 — и то и другое для части или всех развивающих.
   Внутренний процесс может стать развивающим на следующей итерации (переносится со ссылкой на прежний).
   Внутренний процесс ЗАПРЕЩЕНО назначать противоположностью.

### 4.2. Порядок построения мира

1. `FindP0`.
2. Пучок P0 с итерациями. Если противоположность не найдена за `iterations_max` — повтор с шага 1 с
   другим P0 (А 3.1 и опыт: простейшее может не найтись сразу), не больше `p0_attempts`; затем мир
   сохраняется со статусом `no_opposite`.
3. Противоположность записывается из `opposite_candidate`.
4. Пучок противоположности с итерациями (корень — противоположность).
5. `Contradiction`.
6. Пучок противоречия с итерациями (корень — противоречие: то, что P0 и противоположность дают вместе).
7. `Resolve`.
8. Сохранение версии мира.

## 5. Адаптер и пересмотр

### 5.1. Адаптер

- `WorldAdapter(world).brief()` — компактное изложение мира для агента: P0, главные развивающие процессы,
  противоположность, противоречие, разрешение; у каждого процесса — `id`. Размер ограничен (`brief_max_chars`).
- Адаптер не зависит от фреймворка агента: даёт текст для системного промпта или контекста и функцию разбора
  пометки агента. Для тестов — простой собственный цикл агента (модель + инструменты).
- ОБЯЗАТЕЛЬНО: агент в своём обычном ответе (без отдельного вызова) возвращает пометку
  `world_fit: {"fits": true|false, "process_ids": [...], "note": "..."}` — укладывается ли новое в мир и
  с какими процессами оно связано.

### 5.2. Локальный пересмотр

1. Пометка `fits: false` → `ReviseWorld` получает данные агента и названные процессы.
2. Затронутый участок = названные процессы + вытекающие из них (`derived_from`, `parent_id`) в том же пучке.
3. Новая итерация (А 4.6) только по пучку с затронутым участком; вход `NextDeveloping`/`Internals`/`Compare`
   дополняется данными агента.
4. Противоположность, противоречие, разрешение пересчитываются, только если затронутый участок их касается
   (противоположность внутри участка, либо изменился пучок, на котором они построены).
5. Новая версия мира; запись в `revisions`. Старая версия остаётся.
6. Предел `revisions_per_session`, чтобы шумные данные не перестраивали мир бесконечно.

## 6. Настройки (начальные значения, произвольные — владелец)

```text
developing_per_iteration = 3..5      # нейросеть выбирает число в этих пределах
internals_per_developing = 2..3
iterations_max           = 3         # для каждого пучка
p0_attempts              = 3
form_retries             = 2
brief_max_chars          = 4000
revisions_per_session    = 3
builder_model            = openai:gpt-5
agent_model              = настраивается отдельно
```

## 7. Инструменты внутри блоков

Инструменты не являются этапом после разрешения. Любой блок построителя может получить список инструментов
(поиск, чтение документов области, вычисления) и вызвать их внутри своего вызова, если ему нужны факты.
Результат инструмента входит в работу блока и в передачу дальше. По умолчанию инструменты у построителя
выключены; включаются в настройках области.

## 8. Наблюдаемость

Журнал `jsonl` на каждый прогон: для каждого вызова блока — блок, пучок, итерация, вход (передача),
выход, число токенов, время, повторы формы. Отдельная команда печатает мир в читаемом виде.

## 9. Проверка

1. Заглушка модели: тесты на каждый блок (форма, повтор при плохой форме), на механику пучка (порядок
   `NextDeveloping`, параллельность `Internals`, остановка, варианты А 4.6, запрет внутреннего как
   противоположности), на повтор P0, на сохранение версий, на локальный пересмотр (затронут только участок).
2. Одна живая пробная сборка мира на одной области до любых серий.
3. ContractNLI: мир «проверка договоров о неразглашении» строится один раз; агент в этом мире проходит пары
   «договор + утверждение»; сравнение с обычной моделью на тех же парах; случаи отбираются по повторам.
4. Затем медицина (SciFact/HealthVer) и финансы (FinanceBench) — скачивание только с согласия владельца.
5. В каждом отчёте: качество, токены, время; одиночный прогон не считается выводом.
