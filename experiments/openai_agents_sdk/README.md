# Эксперимент: OpenAI Agents SDK Prototype

## 1. Цель эксперимента
Создать изолированный эталонный прототип мультиагентной системы на базе официального **OpenAI Agents SDK** (`openai-agents`) внутри репозитория фреймворка `DialecticAI` без модификации существующего кода фреймворка. 
Цель — на практике исследовать архитектурную модель SDK, его механизмы оркестрации, передачи управления, работы с инструментами, состоянием, трассировкой и обработкой ошибок для последующего сравнительного анализа с архитектурой собственного фреймворка.

## 2. Архитектура

Прототип реализует последовательный конвейер с динамической передачей эстафеты (Handoffs):

```text
User
  ↓
Triage / Planner
  ↓
Analysis Agent
  ↓
Tools (calculate_statistics, compare_datasets)
  ↓
Analysis Agent
  ↓
Reviewer (Synthesis)
  ↓
Final answer (Structured Output)
```

## 3. Роли трёх агентов

1. **Planner_Agent (Triage / Planner):**
   - Получает исходный запрос пользователя.
   - Декомпозирует задачу на концептуальную часть (объяснение среднего) и прикладную (выбор двух контрастных групп данных).
   - Формирует план выполнения, не решая вычислительную задачу самостоятельно.
   - Выполняет нативный `handoff` агенту `Analysis_Agent`.

2. **Analysis_Agent (Quantitative Analysis):**
   - Получает план и исходный контекст.
   - Вызывает зарегистрированные инструменты (`compare_datasets` или `calculate_statistics`).
   - Анализирует фактические числовые результаты (среднее, медиану, диапазон, дисперсию).
   - Формирует предварительные аналитические выводы о расхождении метрик.
   - Выполняет нативный `handoff` агенту `Reviewer_Agent`.

3. **Reviewer_Agent (Synthesis / Quality Reviewer):**
   - Получает историю диалога и аналитическую выжимку.
   - Сверяет числовые утверждения с реальными результатами вычислений.
   - Отсекает промежуточный технический шум.
   - Формирует финальный структурированный ответ пользователю по схеме `FinalAnalysisReport`.

## 4. Используемые возможности OpenAI Agents SDK

- `Agent`: декларативное объявление сущности агента с системными инструкциями, моделью, набором инструментов и списком доступных переходов.
- `Runner`: асинхронный автономный цикл выполнения (`Runner.run`), управляющий вызовами модели, инструментов и сменой агентов.
- `function_tool`: автоматическая генерация JSON Schema параметров из аннотаций типов Python и docstring.
- `handoff`: нативная передача управления между агентами с сохранением контекста и созданием мета-инструмента делегирования.
- `TracingProcessor` и `Span`: встроенная объектная модель трейсинга жизненного цикла прогона.
- `RunHooks`: хуки жизненного цикла (`on_agent_start`, `on_handoff`, `on_tool_start`, `on_tool_end`).
- `output_type`: нативная принудительная типизация финального ответа через Pydantic-схему (`FinalAnalysisReport`).

## 5. Механизм оркестрации
Оркестрация децентрализована на уровне декларации переходов:
- Запуск осуществляется вызовом `Runner.run(starting_agent=planner, input=user_query)`.
- Переходы между этапами осуществляются моделью через вызовы специальных сгенерированных инструментов делегирования (`transfer_to_analyst`, `transfer_to_reviewer`).
- `Runner` перехватывает факт handoff, обновляет текущего активного агента и продолжает цикл размышления в рамках того же общего сеанса выполнения, пока терминальный агент (`Reviewer_Agent`) не вернет финальный ответ.

## 6. Context и State
1. **История диалога (Conversation History):** Единая упорядоченная последовательность сообщений, включающая пользовательский ввод, мысли агентов, вызовы инструментов, их результаты и события передачи эстафеты. При handoff вся история передается целевому агенту.
2. **Контекст прогона (Run Context):** Экземпляр класса `ExperimentContext` передается в аргумент `context=` метода `Runner.run` и доступен компонентам и хукам через `RunContextWrapper`.

## 7. Tools (Инструменты)
Реализованы в `experiments/openai_agents_sdk/tools.py`:
- `calculate_statistics(values: list[float])`: считает `count`, `mean`, `median`, `min`, `max`, `std_dev`.
- `compare_datasets(dataset_a: list[float], dataset_b: list[float])`: сравнивает две выборки, вычисляет дельту средних, дельту медиан, диапазоны и выявляет маскировку перекосов равными средними.

## 8. Tracing (Трассировка)
- SDK автоматически отслеживает создание трейсов (`Trace`), вложенные спаны агентов (`AgentSpanData`), генерацию модели (`GenerationSpanData`), вызовы инструментов (`FunctionSpanData`) и переходы (`HandoffSpanData`).
- В эксперименте подключен пользовательский `CustomTraceProcessor(TracingProcessor)` через `add_trace_processor()`, собирающий события в единый структурированный журнал.
- Дополнительно используется `PipelineRunHooks(RunHooks)` для интерактивного логирования в консоль.

## 9. Error Handling (Обработка ошибок)
- Входные данные инструментов валидируются на уровне Python (проверка типов, пустого списка, `NaN`/`Inf`).
- При возникновении исключения (`ValueError`, `TypeError`) SDK перехватывает ошибку и транслирует её в сообщение с ошибкой инструмента (Tool Call Error).
- Модель видит сообщение об ошибке в следующем витке генерации и получает возможность скорректировать аргументы или стратегию без аварийного падения всего процесса.

## 10. Установка зависимостей

В окружении проекта:
```bash
pip install -r experiments/openai_agents_sdk/requirements.txt
```

## 11. Запуск эксперимента

Запуск основного сценария (включая проверку ошибок и конвейера):
```bash
python -m experiments.openai_agents_sdk.main
```

Для выполнения реальных запросов к LLM требуется задать переменную окружения:
```bash
set OPENAI_API_KEY=sk-...
```
При отсутствии `OPENAI_API_KEY` скрипт штатно отрабатывает в режиме офлайн-валидации: проверяет работу инструментов, демонстрирует обработку ошибок, выполняет численные расчеты на контрастных датасетах и показывает трассу перехода агентов.
