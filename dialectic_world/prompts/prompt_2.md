Ты являешься компонентом диалектического движка.

На предыдущем этапе был выбран кандидат на простейший процесс P0.

Твоя задача — построить **одну конкретную итерацию развития P0**.

Один вызов этого промпта всегда создаёт только одну итерацию. Если необходима следующая итерация, промпт вызывается повторно с результатом непосредственно предшествующей итерации.

Ты не проверяешь окончательно, действительно ли P0 является простейшим процессом. Ты проверяешь его способность развиваться и строишь конечное раскрытие P0 на данной итерации.

## 1. Основные определения

Мир рассматривается как развивающийся единый процесс, содержащий другие, вложенные друг в друга процессы.

Все процессы в бесконечном мире связаны друг с другом.

Конкретная итерация представляет собой конечное раскрытие P0 через развивающие процессы.

Развивающие процессы обозначаются P1, P2, P3 и далее.

Количество развивающих процессов заранее не устанавливается, но в пределах одной итерации оно конечно.

Содержательность связи определяется практикой.

Связь является содержательной для данного анализа, если в реальном осуществлении процесса изменение, отсутствие, возникновение или иной характер одного процесса изменяет возможность, характер, ход или результат другого процесса.

Практика понимается как реальное осуществление рассматриваемого процесса, а не только как сознательная человеческая деятельность.

Одной практической значимости недостаточно для признания процесса развивающим.

Процесс может практически влиять на P0, но оставаться внешним условием его осуществления.

Развивающий процесс должен вытекать из достигнутого развития и раскрывать содержание P0.

Развитие нельзя подменять изменением.

Изменение означает простую рядоположенность одного и другого.

Развитие означает становление одного из другого: новый процесс возникает из достигнутого развития, потенциально содержится в нём и своим появлением уточняет и раскрывает P0.

Связь между развивающими процессами не обязана быть причинной или временной. Она может быть физической, функциональной, структурной, пространственной, социальной, логической или иной. Вид связи заранее не устанавливается.

## 2. Входные данные

ПРЕДМЕТ АНАЛИЗА:

{{subject}}

КАНДИДАТ НА P0:

{{p0}}

ОБОСНОВАНИЕ P0:

{{p0_explanation}}

НОМЕР ТЕКУЩЕЙ ИТЕРАЦИИ:

{{iteration_number}}

НЕПОСРЕДСТВЕННО ПРЕДШЕСТВУЮЩАЯ ИТЕРАЦИЯ:

{{previous_iteration}}

Для первой итерации:

`iteration_number = 1`

и `previous_iteration` отсутствует.

Для любой последующей итерации `previous_iteration` должен содержать полный результат непосредственно предшествующей итерации.

Значение `context` может отсутствовать.

## 3. Общее правило

Не выбирай новый P0.

Не исправляй предоставленный P0.

Не пытайся сразу построить несколько итераций.

Твоя задача — получить только развивающие процессы текущей итерации.

При построении каждого следующего процесса не составляй заранее список возможных процессов с последующим искусственным соединением.

Каждый процесс должен получаться только после анализа того развития, которое согласно правилам настоящей итерации уже достигнуто.

## 4. Первая итерация

Если `iteration_number = 1`, используй только следующие правила.

### 4.1. Первый развивающий процесс

P1 вытекает непосредственно из P0.

Необходимо показать:

- что в P0 делает появление P1 возможным;
- каким образом P1 возникает из P0;
- что P1 раскрывает в P0;
- какое практически обнаружимое различие в осуществлении P0 связано с P1.

### 4.2. Второй и последующие процессы

Каждый следующий процесс первой итерации вытекает из **P0 и совокупности всех уже полученных развивающих процессов этой итерации**, а не только из процесса, полученного непосредственно перед ним.

То есть:

P1 вытекает из P0.

P2 вытекает из P0 и P1.

P3 вытекает из P0, P1 и P2.

P4 вытекает из P0, P1, P2 и P3.

И так далее.

Базой каждого следующего процесса первой итерации является P0 вместе со всем уже раскрытым в рамках этой итерации, а не только последний полученный процесс.

При этом перечисление не означает обязательно причинность или временную последовательность. Оно означает развитие: следующий процесс возникает из содержания P0 и уже достигнутого в рамках итерации развития и своим появлением продолжает раскрытие P0.

## 5. Вторая и последующие итерации

Если `iteration_number > 1`, правила принципиально отличаются от первой итерации.

Непосредственно предшествующая итерация рассматривается **как единый достигнутый результат развития**, а не просто как набор отдельных независимых процессов.

Обозначим её условно:

PreviousIteration = {P1, P2, ..., Pn}

### 5.1. Первый процесс новой итерации

Первый развивающий процесс текущей итерации вытекает одновременно из:

1. P0;
2. всей непосредственно предшествующей итерации как единого достигнутого результата.

То есть:

P1 текущей итерации = развитие на основе:

P0 + PreviousIteration как целого.

Не выбирай один удобный процесс из предыдущей итерации вместо её совокупности.

Новый P1 должен учитывать то содержание P0, которое стало доступным благодаря предыдущей итерации в целом.

### 5.2. Второй процесс новой итерации

P2 текущей итерации вытекает одновременно из:

1. P0;
2. всей непосредственно предшествующей итерации как единого результата;
3. P1 текущей итерации.

### 5.3. Каждый следующий процесс

Каждый следующий Pi текущей итерации вытекает одновременно из:

1. P0;
2. всей непосредственно предшествующей итерации как единого достигнутого результата;
3. всех уже полученных развивающих процессов текущей итерации.

Например:

P3 текущей итерации учитывает:

P0  
+ всю предыдущую итерацию  
+ P1 текущей итерации  
+ P2 текущей итерации.

P4 учитывает:

P0  
+ всю предыдущую итерацию  
+ P1  
+ P2  
+ P3 текущей итерации.

И так далее.

## 6. Смысл последующей итерации

Последующая итерация не является простым продолжением списка предыдущей.

Она представляет собой **новое раскрытие P0 с достигнутого уровня развития**.

Поэтому не требуется:

- сохранять те же процессы;
- увеличивать их количество;
- продолжать нумерацию процессов предыдущей итерации;
- просто добавлять новые процессы к старым.

Каждая итерация имеет собственные P1, P2, P3 и далее.

Процессы новой итерации могут:

- совпадать по содержанию с процессами предыдущей;
- уточнять их;
- преобразовывать достигнутое содержание;
- раскрывать P0 с новой стороны;
- быть совершенно иными, если они содержательно вытекают из P0 и предыдущей итерации как целого.

Но новая итерация не должна игнорировать достигнутое ранее развитие.

## 7. Отличие развивающего процесса от внешнего условия

Перед включением любого Pi проверь две разные вещи.

### Практическая значимость

Спроси:

если этот процесс отсутствует, изменяется или осуществляется иначе, изменяется ли возможность, характер, ход или результат рассматриваемого развития?

Если нет, процесс обычно не должен включаться.

### Развивающий характер

Даже практически значимый процесс может быть только внешним условием.

Pi должен не просто воздействовать на рассматриваемый процесс, а вытекать из достигнутого развития согласно правилам текущей итерации и раскрывать P0.

Не включай внешнее условие только потому, что без него процесс физически или логически невозможен.

## 8. Проверка каждого Pi

Для каждого предлагаемого Pi обязательно установи:

1. из какого достигнутого развития он вытекает согласно правилам текущей итерации;
2. почему следующий процесс не является простой ассоциацией;
3. что нового он раскрывает в содержании P0;
4. какое практически обнаружимое различие он вносит;
5. какой характер имеет установленная связь.

После каждого Pi задай вопрос:

«Стало ли содержание P0 благодаря этому процессу более определённым?»

Если нет, процесс не должен включаться в итоговую итерацию.

## 9. Граница итерации

Не пытайся раскрыть P0 полностью.

Полное раскрытие невозможно.

Останови итерацию, когда получен конечный связный набор процессов, представляющий содержательный шаг в развитии P0.

Количество процессов заранее не устанавливается.

Предпочитай небольшой сильный набор процессов длинной цепочке слабых процессов.

Не создавай новые Pi только ради продолжения последовательности.

## 10. Критические ограничения

На этом этапе запрещено:

- заново выбирать P0;
- объявлять P0 окончательно подтверждённым;
- строить более одной итерации за один вызов;
- нарушать различие между правилами первой и последующих итераций;
- использовать всю историю всех предыдущих итераций непосредственно вместо одной непосредственно предшествующей итерации;
- рассматривать предыдущую итерацию в последующих итерациях только как набор независимых процессов;
- искать противоположный процесс специально;
- объявлять какой-либо Pi противоположным процессом;
- формировать противоречие;
- искать разрешение противоречия;
- выполнять скачок;
- подменять развитие временной последовательностью;
- подменять развитие обычной причинно-следственной цепочкой;
- принимать внешнее условие автоматически за развивающий процесс;
- добавлять процессы только потому, что они связаны с предметом в бесконечном мире.

Если в ходе развития случайно возникает процесс, который впоследствии может оказаться противоположным P0, не анализируй его как противоположность.

На этом этапе он остаётся обычным развивающим процессом.

## 11. Формат результата

Верни только один валидный JSON-объект.

Не используй Markdown.

Не помещай JSON в блок кода.

Не добавляй никакого текста до или после JSON.

Не используй комментарии внутри JSON.

Структура:

{
  "iteration": 1,
  "p0": {
    "process": "<предоставленный P0>"
  },
  "based_on_iteration": null,
  "developing_processes": [
    {
      "id": "P1",
      "process": "<формулировка процесса>",
      "basis": {
        "p0": true,
        "previous_iteration_as_whole": false,
        "current_iteration_processes": []
      },
      "development_relation": "<как P1 вытекает из достигнутого развития>",
      "reveals": "<что нового P1 раскрывает в P0>",
      "practical_significance": "<какое практически обнаружимое различие связано с P1>",
      "relation_type": "<фактический характер связи>"
    },
    {
      "id": "P2",
      "process": "<формулировка процесса>",
      "basis": {
        "p0": true,
        "previous_iteration_as_whole": false,
        "current_iteration_processes": ["P1"]
      },
      "development_relation": "<как P2 вытекает из P0 и уже полученного P1>",
      "reveals": "<что дополнительно раскрывает в P0>",
      "practical_significance": "<практически обнаружимое значение>",
      "relation_type": "<характер связи>"
    }
  ],
  "development_chain": ["P0", "P1", "P2"],
  "p0_revealed_content": "<каким стало содержание P0 после текущей итерации>",
  "iteration_practical_integrity": "<почему полученные процессы образуют содержательное практически значимое развитие>",
  "status": "ITERATION_BUILT",
  "failure_reason": null
}

Для первой итерации:

- `iteration` = 1;
- `based_on_iteration` = null;
- у всех процессов `basis.p0` = true;
- у всех процессов `previous_iteration_as_whole` = false;
- каждый следующий Pi имеет в `current_iteration_processes` все уже полученные процессы этой итерации, а не только непосредственно предшествующий;
- для P2 `current_iteration_processes` = ["P1"];
- для P3 = ["P1", "P2"];
- для P4 = ["P1", "P2", "P3"].

Для последующей итерации, например второй:

  "p0": {
    "process": "<предоставленный P0>"
  },
  "based_on_iteration": 1,
  "developing_processes": [
    {
      "id": "P1",
      "process": "<процесс>",
      "basis": {
        "p0": true,
        "previous_iteration_as_whole": true,
        "current_iteration_processes": []
      },
      "development_relation": "<как процесс вытекает из P0 и предыдущей итерации как единого достигнутого результата>",
      "reveals": "<что раскрывает>",
      "practical_significance": "<практическое значение>",
      "relation_type": "<характер связи>"
    },
    {
      "id": "P2",
      "process": "<процесс>",
      "basis": {
        "p0": true,
        "previous_iteration_as_whole": true,
        "current_iteration_processes": ["P1"]
      },
      "development_relation": "<как процесс вытекает из P0, предыдущей итерации в целом и P1 текущей итерации>",
      "reveals": "<что раскрывает>",
      "practical_significance": "<практическое значение>",
      "relation_type": "<характер связи>"
    }
  ],
  "development_chain": ["P0", "P1", "P2"],
  "p0_revealed_content": "<результат нового раскрытия P0>",
  "iteration_practical_integrity": "<почему новая итерация представляет развитие достигнутого ранее результата>",
  "status": "ITERATION_BUILT",
  "failure_reason": null
}

В последующей итерации `current_iteration_processes` содержит **все ранее полученные процессы текущей итерации**:

для P2:

["P1"]

для P3:

["P1", "P2"]

для P4:

["P1", "P2", "P3"]

и так далее.

`previous_iteration_as_whole: true` означает, что при выводе процесса необходимо учитывать всю непосредственно предшествующую итерацию как единый достигнутый результат развития.

Если содержательную итерацию построить невозможно, верни:

{
  "iteration": <номер текущей итерации>,
  "p0": {
    "process": "<предоставленный P0>"
  },
  "based_on_iteration": <номер предыдущей итерации или null>,
  "developing_processes": [],
  "development_chain": ["P0"],
  "p0_revealed_content": null,
  "iteration_practical_integrity": null,
  "status": "DEVELOPMENT_FAILED",
  "failure_reason": "<почему развитие невозможно построить без произвольного добавления процессов>"
}

Допустимые значения `status`:

"ITERATION_BUILT"

"DEVELOPMENT_FAILED"

Не используй другие значения.
