# Снимок: как промпты построителя мира устроены сейчас, до пересмотра их схемы

Зафиксировано 27 сентября 2026, до какой-либо правки промптов. Причина: схема промптов меняется
серьёзно (владелец готовит промпты отдельно, вне кода, и они заменят нынешние) — этот файл
документирует ровно то, что было до этой правки, чтобы было с чем сравнивать и что при желании
откатить. Ничего в этом файле не является предложением или оценкой — только дословное описание
текущего состояния кода.

## Диагноз (зафиксированная владельцем причина пересмотра)

Отдельного промпта как объекта в проекте нет. Есть:

- **Алгоритм** (`dialectic_world/method.py`) — дословный текст пунктов владельца, вынесен отдельно
  от кода блоков.
- **Промпт каждого блока** — f-строка внутри функции блока в `dialectic_world/builder/blocks.py`,
  собранная из текста задания (написан разработчиком движка, не владельцем), нескольких цитат из
  `method.py` по номерам пунктов, состояния мира и требуемой JSON-схемы ответа.

То есть сам текст промпта (не алгоритма) нигде не существует отдельно от кода: чтобы его увидеть,
изменить или перенести в другой движок, нужно читать/писать Python. Это и есть предмет пересмотра.

## Общие для всех блоков куски (`dialectic_world/builder/blocks.py`)

Эти фрагменты не самостоятельные промпты — они подставляются внутрь промпта каждого блока.

```python
# blocks.py:40-43
CARRY_FIELD = '"carry": "передача следующему блоку: 1-3 предложения — сжатое развитие до этого места, включая твой результат"'
TRANSITION_RULE = ('Каждый процесс записывается как переход одного процесса в другой (п. 1.1): "from" — процесс, который '
                   'переходит, "to" — процесс, в который он переходит (оба словами, не номерами), "statement" — '
                   'краткая формулировка перехода.')
```

`language_note(ctx, default)` (blocks.py:48-56) — если в настройках (`Settings.output_language`)
задан язык, возвращает `"Answer in <English|Russian|...>."`; иначе возвращает `default` — свою
для каждого блока фразу вида «Отвечай на языке описания области./корня./процессов.».

`_tools_note(ctx)` (blocks.py:112-117) — если построителю дали инструменты, добавляет в конец
промпта список `- имя: описание` и инструкцию вернуть `{"tool": "...", "args": {...}}` вместо
ответа блока. По умолчанию инструментов нет, эта часть пустая.

Все промпты уходят одним `user`-сообщением через `ask()` (blocks.py:134-166): ответ разбирается
как JSON (`extract_json`), проверяется по правилам блока (`parse`); при ошибке формы модели
показывается текст ошибки и просьба переспросить, не больше `Settings.form_retries` раз (сейчас 2);
успешного ответа с непустым `"carry"` — заносится в `ctx.carry` и виден следующему блоку как
«Передача от предыдущего блока: …». Никакой модели-судьи нет нигде в цепочке.

## Алгоритм, на который ссылаются промпты (`dialectic_world/method.py`, дословно)

```text
1.   Мир принимается как развивающийся единый процесс, содержащий другие, вложенные друг в друга,
     процессы.
1.1. Когда один процесс переходит в другой процесс, то это и называется процессом. Процесс может
     быть задан только как переход одного процесса в другой процесс.
2.   Процессы развиваются.
2.1. "Процессы развиваются" означает, что из простейшего процесса появляются развивающие процессы,
     причем развивающие процессы уже содержались потенциально в простейшем процессе, а появление
     развивающих процессов уточняет, раскрывает простейший процесс. Такое непрерывное появление
     раскрывающего процесса из простейшего процесса и обратно называют становлением.
3.   Процесс развивается из простейшего процесса.
3.1. Простейшим считается такой процесс, который одновременно: 1) сам получен из скачка (смотрите
     ниже); 2) из простейшего процесса вытекают развивающие его процессы, приближение к полной
     совокупности которых и является развитием простейшего процесса.
3.2. Обозначается простейший процесс как P0.
3.3. Простейший процесс развивается в бесконечном мире. Поэтому нельзя достигнуть полной
     совокупности развивающих процессов, что является дополнительным смыслом самого понятия
     развития.
3.4. В своей бесконечности мир един, поэтому любой процесс на бесконечности связан с любым
     процессом.
3.4.1. Одновременно с этим простейший процесс берется на конкретной итерации. В конкретной
     итерации простейший процесс раскрывается через любые иные процессы. Под итерацией понимается
     именно сведение бесконечности к конечному набору развивающих процессов.
4.   Простейший процесс раскрывается через развивающие процессы. Под раскрытием понимается
     связывание простейшего процесса с другими процессами на конкретной итерации.
4.1. Обозначаются развивающие процессы как P1, P2 и т.д. Задаются развивающие процессы нейросетью
     в соответствии с требованиями настоящего алгоритма к развивающим процессам. Количество
     развивающих процессов изменяется на каждой итерации, но могут быть и совпадения по
     количеству.
4.2. На конкретной итерации каждый развивающий процесс вытекает из простейшего процесса и
     предшествующих развивающих процессов этой итерации и предшествующих итераций. Это правило не
     касается первой итерации, для которой нет предшествующей итерации. На первой итерации каждый
     развивающий процесс вытекает из простейшего процесса и каждого уже полученного развивающего
     процесса первой итерации.
4.3. Каждый развивающий процесс связан с последующим развивающим процессом. В этом смысле
     "вытекает из развивающего процесса" означает, что последующий на данной итерации или
     последующий на следующих итерациях развивающий процесс связан с предыдущими развивающими
     процессами. Вид, степень, характеристика такой связи заранее не устанавливаются, могут быть
     любыми.
4.4. Дело обстоит следующим образом. Мир является бесконечным. В своей бесконечности он един.
     Поэтому любой процесс связан с любым процессом на бесконечности. Однако в конкретной итерации
     простейший процесс связан с развивающими процессами именно по правилам настоящего алгоритма.
4.5. Каждый развивающий процесс имеет внутренние процессы. Для определения внутренних процессов
     развивающий процесс принимается за простейший, затем находятся его развивающие процессы без
     дальнейшей вложенности. Внутренние процессы задаются нейросетью в соответствии с требованиями
     настоящего алгоритма. Количество и состав внутренних процессов изменяются между итерациями,
     однако допускаются совпадения по количеству и отдельным процессам. Внутренние процесс одного
     и того же развивающего процесса на разных итерациях должны быть связаны.
4.6. На каждой итерации: 1) либо сохраняется полный состав развивающих процессов, но изменяется
     состав внутренних процессов; 2) либо количество развивающих процессов изменяется в сторону
     уменьшения или увеличения, но без изменения внутренних процессов; 3) либо количество
     развивающих процессов изменяется в сторону уменьшения или увеличения, причем изменяются также
     внутренние процессы части или всех развивающих процессов.
4.7. На каждой итерации: 1) развивающие процессы сравниваются с простейшим процессом; 2)
     развивающие процессы сравниваются между собой; 3) внутренние процессы одного развивающего
     процесса сравниваются с внутренними процессами других развивающих процессов.
4.8. В ходе развития простейшего процесса среди развивающих процессов обнаруживается
     противоположный процесс.
5.   Противоположным считается процесс, который в своем развитии исключает существование
     простейшего процесса.
5.1. Исключение существования простейшего процесса не означает уничтожение простейшего процесса.
     Исключение существования означает, что для развития противоположного процесса простейший
     процесс не требуется.
6.   Простейший процесс и противоположный процесс, взятые в единстве их развития, являются
     противоречием.
7.   Разрешение противоречия осуществляется скачком. Это не означает, что разрешающий процесс
     нельзя объяснить. Это означает, что разрешающий процесс объясняется как разрешение
     противоречия.
7.1. Разрешение противоречия означает либо появление такого процесса, который заменяет простейший
     и противоположный, вбирая их в себя в своем развитии, либо появление такого процесса, который
     делает возможным продолжение существования противоречия до его разрешения в процессе, который
     заменит простейший и противоположный.
9.   Нельзя подменять развитие изменением. Отличие изменения от развития состоит в том, что
     изменение это простая рядоположенность одного и другого, а развитие это становление одного и
     другого, переход одного в другое. Изменение просто дает одно и другое, а развитие показывает,
     как одно переходит в другое и наоборот.
```

## Что вокруг промптов (код, который решает, когда какой блок вызвать — сам не содержит текста промпта)

- `dialectic_world/builder/bundle.py` — ведёт итерации одного пучка: `NextDeveloping` строго
  последовательно, затем `Internals` для всех развивающих параллельно (`asyncio.gather`), затем
  один `Compare`; следующая итерация выполняет вариант А 4.6, выбранный в `Compare`
  (`retire`/`promote`/`redo_internals`).
- `dialectic_world/builder/build.py` — верхний порядок: `FindP0` → пучок P0 (до `p0_attempts` раз,
  пока не найдётся противоположность) → пучок противоположности → `Contradiction` → пучок
  противоречия → `Resolve` → сохранение мира.
- `dialectic_world/config.py` (`Settings`) — все числа, упоминаемые в промптах как пределы:
  `developing_min/max`, `internals_min/max`, `iterations_max`, `p0_attempts`, `form_retries`,
  `tool_calls_max`, `output_language`, `builder_model`.
- `dialectic_world/llm/providers.py` — как промпт реально уходит в модель (`OpenAICompatible`/
  `Anthropic`, HTTP, повторы при 429/5xx); не содержит текста промптов.
- `dialectic_world/trace.py` — журнал: для каждого вызова блока пишет ровно тот текст промпта,
  который ушёл (`prompt=prompt` в `ask()`, blocks.py:163), и разобранный ответ — то есть журнал
  прошлых прогонов (`data/traces/*.jsonl`) сейчас единственное место, где реальный текст промпта
  виден отдельно от кода, но только постфактум, для уже сделанного вызова.

## Итог снимка

Всего в проекте пять смысловых слоёв, из которых первые два сейчас слиты в один файл:

1. **Алгоритм** (`method.py`) — отдельно, дословный, стабильный источник истины.
2. **Текст промпта каждого блока** — сейчас внутри Python-кода `blocks.py`, не отдельным
   артефактом; следующий шаг — вынести.
3. **Оркестрация** (`bundle.py`, `build.py`) — какой блок когда вызывается, в каком порядке, с
   какими пределами; не содержит текста промптов, но передаёт в них состояние.
4. **Транспорт к модели** (`llm/`) — не содержит текста промптов.
5. **Наблюдаемость** (`trace.py`) — единственное место, где текст промпта виден без чтения кода,
   но только для уже прошедших вызовов.
